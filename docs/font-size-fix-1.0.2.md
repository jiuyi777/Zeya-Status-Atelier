# 字体体积修复（1.0.2）

基于已发布的 1.0.1（0d4cad40ba79f3fa5d7f5ba4f45fc43144fdac5c），单独修复导出体积。

旧生成器把 8,245,656 字节的汇文明朝转成 10,994,208 字符的 Base64，放进每个参考状态栏正则。酒馆导出 PNG 又对角色 JSON 编码，并写入 chara、ccv3 两份兼容数据，仅字体就增加 29,317,888 字节（约 28 MiB）。

修复后的行为：

- 16 款参考状态栏共用固定版本的公开字体链接；预览读取插件中的字体文件。
- 本地字体进入导出器时，按完整 SHA-256 识别这份字体并保留为外链。旧版内嵌字体也按相同规则替换。
- 其他字体保持原内容；超过 256 KiB 的内嵌字体停止导出并提示改用外链。完成图片等资源处理后，正则 JSON 还会检查 1 MiB 上限。
- 构建器不再生成 reference-font-data.js。升级时可删除该旧文件。
- 手机以 HTTP 访问酒馆时也能完成字体校验。
- 安装状态栏时，同时清理当前正则列表里旧版内嵌的这份字体，包含保留的旧模板；保留原 ID、自定义内容和启用状态。保存后回读整份列表，核实旧字体清理也已保存。

更新后，在目标角色内重新安装状态栏，即可同时清理已有正则里的这份字体，再导出角色卡。对于已经导出的独立文件，也可以使用下面的副本工具保留原内容和交互：

```text
node scripts/compact-card-fonts.mjs 原卡.png 瘦身副本.png
```

也支持 JSON 角色卡和单个正则 JSON。工具只改两处标准正则列表内已确认的汇文明朝数据链接，保留 ID、启用状态、顺序、字段、世界书、开场白和未知字段。PNG 的 chara 与 ccv3 分别处理，各自保留原数据；所有图像块保持原字节。输出文件必须是新文件，不覆盖原卡。

独立卡片首次加载字体需要访问公开字体文件。该链接内容与插件字体的 SHA-256 相同。这里的 1 MiB 是新增状态栏正则的体积上限，不是整张角色卡的体积限制。

验证：379 项测试和静态检查通过。使用本机 SillyTavern 的 PNG 写入器，完整状态栏样本由 29,478,800 字节降到 161,176 字节，再次导出体积不增长；非字体角色数据及图像块保持不变。安装回归覆盖旧正则保留、重复安装、切换角色中止，以及保存后回读确认。手机端字体显示仍需在实际设备查看。
