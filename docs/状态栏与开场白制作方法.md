# 九一工坊：原窗口制作方法与脚本版接入说明

整理日期：2026-10-24。作者署名：九一。

## 这份文档记录什么

依据原聊天「接入预览与主页优化」可读记录、已保存的八款原版 HTML、现有九一工坊源码整理。原聊天要求把大幅生成图片上传 GitHub，再把开场白接入九一工坊；本次进一步改为酒馆助手脚本交付。原聊天完整执行记录目前不能全部读取，因此下面把可以从成品核实的方法与本次补上的工程步骤分开。

开场白主页用于选择故事入口；状态栏用于展示每轮剧情中的人物状态。两者共享工坊入口，但数据来源、生成规则与使用时机不同。

## 一、原版美化如何组成

八款成品分别为：双幅飞鸟、花笺序页、蓝墨来信、蓝花来信、星夜云层、墨迹拼贴、靛蓝序章、花间索引。第九款「旧街来信·图文错落版」尚未取得原文件，不能用相近图片或重新设计的一款冒充。

从这些原文件可以确认：

1. 大幅插画独立于网页文字：使用 WebP 图片，配合纸张、信封、花卉、云层和飞鸟等视觉主体。文字不是烘焙在图片里的固定标题。
2. HTML/CSS 负责排版、裁切、拼贴层级与阅读空间。部分图片经 SVG 的 image/use 复用，并不是每一层都生成新图片。
3. 书页、目录、作品资料、信封展开等交互由脚本控制。折叠目录保留原生 details/summary，作品页面用 data-view 切换。
4. 原样稿用 data-home 标记作品字段，用 data-entry 与 data-entry-field 标记目录条目。样稿里的「旧街来信」「认错人」等仅是试排内容。
5. 原样稿包含本地编辑器和模拟阅读器。它们用于检查外观与交互，不能代替酒馆里的真实开场白切换。

原文件中图片与完整字体以 base64 内嵌，单份约 12–24 MB。本次提取并去重后得到 11 份 WebP 图片与 2 份原版 WOFF2 字体。二进制内容保持不变；来源文件、SHA-256、大小记录在 opening-illustrated-sources/provenance.json。字体仍使用原字体，不静默替换。

## 二、如何制作一款可复用状态栏

### 1. 先确定用途与数据

先列出玩家要读的状态：例如人物、地点、情绪、关系、随身物品。为每个字段确定稳定 ID、中文标签、数据类型、描述，以及单人还是多人结构。不要先画一张写死人物名字的图，再把它当动态状态栏。

九一工坊的 rule-generator.js 管理字段解析、结构归一化、AI 输出说明、正则和配对世界书。status-ai-single.js 管理候选结构与单次生成结果解析；status-worldbook.js 处理世界书目标与条目更新。

### 2. 把视觉结构与实际数值分开

参考图决定构图、素材、排版、留白和交互，不决定用户的角色名、状态内容。模板提供头像位、字段位、文字位、媒体位；当前角色数据或用户填写的配置填入这些位置。

保留原模板独特的拼贴、翻页、折叠和多人切换。不能把不同模板统一成一长列卡片，也不能用几根线或几颗星代替插画主体。

### 3. 用同一字段定义生成显示与模型规则

状态栏正则负责把模型输出的结构化状态转成显示界面；配对世界书负责告诉模型输出什么字段、采用什么结构。字段新增、删除或改名后，两端应重新生成，防止界面等一个字段、模型却输出另一个字段。

静态装饰与每轮变化的状态值分开。写入角色卡前保留其他正则、世界书条目和用户配置，只更新工坊拥有的稳定 ID。

### 4. 先验证代表样稿，再推广

至少检查宽屏和窄屏：文字是否可读、长内容能否滚动、头像裁切是否合适、折叠和翻页是否仍可操作。默认隐藏滚动条外观，保留滚轮、触摸和键盘滚动。

测试用内容应覆盖空值、长中文、特殊字符、零人/一人/多人。不能仅凭一张静态截图证明动态状态正确。

### 5. 完成实际使用链

字段定义 → AI 输出规则/世界书 → 模型结构化输出 → 解析与正则显示 → 保存或导出 → 重新导入 → 下一轮更新。

预览显示正确，只证明排版；正则导出成功，只证明生成。真实酒馆中还要检查安装作用范围、渲染接管、实际状态更新和重开后的保存结果。

## 三、本次八款开场白如何通用化

所有作品标题、副标题、作者、模型、预设、简介和每条目录的标题、线路、摘要，都由当前工坊数据生成。没有把「旧街来信」作为默认真实内容写入用户卡。

- data-home 对应作品字段；data-entry-field 对应真实目录条目。
- 目录按实际 entries 数组生成；不会固定三条，也不把第三条复制成虚假故事。
- 开场白 target 沿用原工坊的一基编号契约，再由现有运行逻辑换算和切换真实 swipe；不能把模板位置当作开场白 ID。
- worldlineId、世界书名称和条目 UID 继续交给现有世界书绑定逻辑处理。
- 样稿模拟阅读器不承担正式跳转；正式入口使用工坊原有导航逻辑。
- 预览只展示和反馈选择，不运行世界书写入或真实开场切换。
- 外观模板分享只带外观配置，不携带真实开场内容和世界书绑定。

原模板的字数变化仍会影响排版，因此制作时要检查长标题、多行简介以及不同条目数量。

## 四、大素材、源码与导出怎样衔接

1. scripts/import-illustrated-originals.mjs 从原版 HTML 提取图片、字体与标记模板，记录来源哈希。
2. opening-illustrated-sources/ 保存可复查模板，内容字段和目录条目已参数化。
3. scripts/build-illustrated.mjs 生成 opening-illustrated-data.js。
4. opening-illustrated.js 负责数据转义、动态目录、局部交互及真实导航接入。
5. opening-home-catalog.js 注册样式；opening-home-generator.js 保持预览和最终正则共用生成器。
6. assets/opening-illustrated/ 托管大素材；导出的正则只引用固定版本 URL，避免每张卡重复嵌入完整字体和图片。

换素材或修模板必须改源文件再构建，不能只改截图或单个导出结果。远程资源使用固定版本 script-v1.1.0，未来替换资源应发新版本并更新引用。

## 五、为什么能做成脚本版

脚本版复用已发布工坊的完整界面与生成器，通过构建把内部模块合并。酒馆自身的角色、世界书、正则管理等模块仍由当前酒馆提供，不从 GitHub 加载另一套宿主代码。

酒馆助手导入的 JSON 是启动脚本；它下载固定版本工坊模块和样式，在酒馆页面挂载原工坊。无需安装九一工坊扩展目录。

- 全局脚本按钮：制作状态栏、制作开场白。
- 原魔杖菜单入口保留。
- 配置继续使用工坊原设置命名空间，已有配置可以沿用。
- 重复脚本或同名扩展同时运行时停止重复挂载。
- 停用时移除界面、返回按钮观察器、事件监听及工坊临时提示注入；已经生成并安装到卡里的成果不随脚本停用删除。
- 图片和字体首次使用需要联网；脚本版依赖酒馆助手及 SillyTavern 的原生模块接口。

本地接口参考：酒馆助手 4.11.2 的脚本按钮、事件与自动卸载声明；宿主调用沿用现有工坊接口。TauriTavern 是否完整提供相同模块路径，需要在对应设备验证，不能用桌面模拟结果替代。

## 六、导入与检查

在酒馆助手的全局脚本库导入 script-version/jiuyi-status-atelier.json 并启用。如果已启用同名九一工坊扩展，先停用扩展以免出现重复入口。随后点击「制作开场白」或「制作状态栏」。

开场白界面展开未收藏外观，选择新增插画款，修改作品资料，读取当前角色额外问候语，再使用原有生成与应用流程。

发布前检查：动态字段、任意目录数量、特殊字符、完整 fenced HTML/body、预览不写宿主、世界书绑定保留、脚本启停、最终 JSON 格式、托管素材可访问。真实设备还应检查进入开场、切换世界线、返回目录和重新打开后的配置。
