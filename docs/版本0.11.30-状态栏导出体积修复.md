# v0.11.30 状态栏导出体积修复

## 原因与变化

部分 01—15 模板内嵌多张高清 PNG，导出时此前只剥离角色卡元数据，没有限制像素尺寸和编码体积。HTML 因此达到数 MB；PNG 卡再将整份角色数据编码进 chara、ccv3 两份载荷，进一步放大文件。媒体设置还保留了随后立即被选定头像替换的模板示意头像。

共享 `makePortableRegex` 导出入口现在将较大的静态 PNG/JPEG/WebP 编码为适合状态栏显示的小图：最长边初始上限 720px、按大小最多尝试 8 次，每张目标不超过 24KiB。使用有损 WebP 并按需要缩图；源素材保留。相同图片只处理一次，重复导出不继续压缩已达标图片。APNG/动画 WebP 与 GIF 保留动画，字体和 SVG 保持原逻辑。压缩失败会停止写入，避免静默产生超大的静态图片数据。

配置头像时，模板示意头像不再进入成品；选定头像继续随卡携带，不需要接收者连接作者设备或安装本插件。安装和下载继续调用同一导出入口。

另修复两类可复现的正则阻塞：内置逐字段正则跨记录回溯、通用正则对截断空白输入的冗余回溯。保持正则 ID、捕获编号、正常字段及安装保存逻辑。此版本不包含尚未确认的手机外观调整。

## 验证与边界

- 225 项测试和静态检查通过。
- 43 个模板在本地浏览器中实际执行共享打包函数，全部完成；导出脚本语法检查通过。
- 11 个多 MB 的模板结果缩小为约 31—79KB（默认无头像样本）。通用模板仍含自身代码；并非所有角色卡都保证低于 1MB。
- 用户提供的 PNG：21,323,251 → 976,043 字节；其中状态栏 7,743,550 → 113,268 字节。卡面图像块、人物数据、世界书、开场白及其他正则保持一致。双载荷回读一致。
- 已证实体积放大的原因和异常输入的同步阻塞路径。尚未在报告卡死的接收者设备中完成实测。

更新插件只修复以后安装/下载的结果；已经分享的旧 PNG 仍携带旧内容。旧卡需要重新生成对应状态栏或使用修正后的成品，不需要删除原聊天或其他正则。

## 为什么此前修复没有覆盖这次问题

2026-09-06 的 0.11.17 将图片等资源随正则打包，解决接收者无法读取作者本机资源的问题。2026-09-10 的提交 794b42d 随后剥离头像 PNG 中的角色卡文字数据，阻止整份角色卡再次嵌入头像。该修复保留像素数据，没有缩小高清素材，也没有移除随后被覆盖的模板示意头像。

当时回归测试验证的是元数据剥离、像素保持和重复导出稳定，没有检查真实模板导出后的图片预算以及最终 PNG 卡体积。因此一个膨胀原因被修复后，另一个共享打包缺陷仍然存在。这属于排查范围和成品验收不足。本次在共享出口加入静态图片体积限制，并用全部 43 个模板和真实 PNG 往返验证补足这条链路。异常文本引发的正则回溯另行复现并修复，接收者设备上的完整卡死现象仍需实际验收。
